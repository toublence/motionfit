이 문서는 2026-07-29 기준 코드 전수 검토, `flutter analyze`(이슈 0건), `flutter test`(59개 전체 통과), 2026-07-22 실기기 검증 기록(docs/LIVE_COACHING_ANALYSIS_2026-07-22.md)을 근거로 작성했다. 카메라 추론이 필요한 항목은 실기기 없이 오늘 재실측할 수 없으므로, 해당 항목은 최신 실기기 기록과 코드 검토를 근거로 판단하고 그 경계를 명시한다.

## 1. 기능 정상 여부 검증 결과

### 1.1 자동 카운팅 — 정상

- `RepDetector` 단위 테스트가 정상 1회/10회, 얕은 왕복, bad-form 조합, standing jitter, 추적 손실, pause/resume, refractory, 중단 하강을 모두 통과한다.
- 2026-07-22 Galaxy S24+ 실기기 재검증에서 10회 중 10회 카운트, 첫 동작부터 누락 없음(캘리브레이션 0.3초/6프레임 단축 적용 후).
- 카운트 음성은 판정 후 0.005~0.13초 안에 발화를 시작했고, 낮은 우선순위 음성을 선점(preempt)하도록 되어 있어 카운트가 밀리지 않는다.
- 남은 리스크: 97% 정확도 주장은 아직 실측 corpus(100 clips/10 subjects/500 reps) 미충족. 다양한 기기·조명·체형 조건은 미검증 상태다(KNOWN_LIMITATIONS 유지).

### 1.2 실시간 자세 분석 음성 코칭 — 정상, "트레이너 체감"은 부분 달성

정상 동작 근거:

- 오판 억제 정책이 코드와 테스트로 고정되어 있다: 같은 문제 최근 3회 중 2회 이상 관찰 시에만 코칭, 안전 관련(뒤꿈치/무릎/상체)은 고신뢰 시 즉시, 같은 큐 3회 반복 내 재발화 금지, 서로 다른 큐 사이 최소 1회 무음 반복(`CoachPolicy` 테스트 통과).
- 카운트는 빠르고 높은 피치, 교정은 안정된 피치로 구분 발화(`SystemTtsCoachEngine`).
- 7/22 실기기 검증에서 정상 자세 반복에는 교정이 0회, 유도된 상체/무릎 문제에는 2회 연속 관찰 후 카운트 직후 교정이 재생됐다. 이전의 `incompleteLockout` 대량 오판, 기준 없는 `heelLift` 오판은 재현되지 않았다.

"트레이너가 옆에 있는 느낌"의 현재 한계 (개선 대상):

1. **목소리 품질**: 시스템 기본 TTS 음성을 사용한다. iOS enhanced/premium 보이스를 명시적으로 선택하지 않아 기기 기본값에 따라 기계음처럼 들릴 수 있다. 이것이 체감 품질의 가장 큰 병목이다.
2. **코칭 시점**: 자세 교정은 반복 완료 후에 나온다. 동작 중(하강 중 "조금 더 깊게") 실시간 큐는 없다. 오탐 억제를 위한 의도된 설계지만, bottom 이벤트 기반의 짧은 실시간 큐 1종은 추가할 여지가 있다.
3. **개인화 부재**: 지난 세션 대비 향상/저하 언급, 이름 호명, 목표 대비 진행 안내가 없다. 세트 시작·완료 문구가 항상 동일하다.
4. **격려 빈도**: 정상 자세여도 3회마다 1번만 격려. 트레이너 체감에는 마지막 2개 반복 "마지막 두 개!", 목표 근접 안내가 효과적이다.

### 1.3 리텐션 기능 — 일부 있음, 핵심 루프는 없음

있는 것:

- 주간 요일별 로컬 리마인더 (기본 **모두 꺼짐**, 19:00, 설정 탭 안에 위치)
- 기록 탭: 월간 캘린더, 일별 집계, 통계(총 횟수, 운동일수, 자주 발생한 자세 문제)
- 중단 세션 복구(홈에서 이어하기), 오프라인 완결 구조

없는 것 (전부 DAU에 직결):

- **스트릭(연속 운동일)** — 없음. 홈/요약 어디에도 연속성 개념이 없다.
- **목표/챌린지** — 일일 목표, 주간 목표, 누적 마일스톤(1,000회 달성 등) 없음.
- **운동 완료 직후 리마인더 제안** — 리마인더가 설정 탭에만 있어 발견율이 낮다. 동기가 가장 높은 순간(첫 운동 완료 직후)에 제안하지 않는다.
- **공유** — 완료 카드/기록 이미지 공유 기능 없음 (`share_plus` 미사용).
- **평점 요청** — `in_app_review` 미사용. ASO 평점 축적 루프가 없다.
- **홈 위젯 / Apple Health 연동** — 없음.
- **측정** — Firebase Analytics는 `app_open` 1개 이벤트만 기록한다. 운동 시작/완료, 온보딩 완료, 리마인더 활성화 등 퍼널 이벤트가 전무해서 D1/D7 리텐션과 개선 효과를 검증할 수단이 없다.

## 2. 광고 미노출 점검 결과 — iOS: 문제 없음

코드·설정 기준으로 구조적 미노출 문제를 찾지 못했다. 일부러 문제를 만들지 않는다.

확인한 근거:

| 항목 | 상태 |
| --- | --- |
| `GADApplicationIdentifier` (Info.plist) | `ca-app-pub-6169297934919363~6579923583` — 광고 유닛과 동일 게시자, 정상 |
| SKAdNetworkItems | 50개 등록 — 정상 |
| ATT → UMP 순서 | ATT 응답 후 UMP 동의 폼 → 동의 확인 후에만 SDK 초기화. 미해결 ATT 위에 UMP를 띄우지 않음 — 정상 |
| 광고 유닛 분기 | release=프로덕션 ID, debug=Google 테스트 ID — 정상 (디버그 빌드에서 실광고가 안 나오는 것은 정상 동작) |
| 네이티브 광고 | 하단 탭 셸(스쿼트/기록/설정 공통) + 휴식 화면. 로드 실패 시 5s→15s→30s→60s 백오프 재시도 — 정상 |
| 전면 광고 | 운동 요약 완료 시, 나중에 하기 저장 시 — 정상 |
| 앱 오픈 광고 | 콜드 스타트(온보딩 완료 후) + 60초 이상 백그라운드 복귀 시, 전면 광고류 3분 간격 제한 — 정상 |
| 초기화 실패 복구 | 초기화 미완료 시 `_initialization` 리셋으로 다음 시도 가능 — 정상 |

코드 밖 요인으로 광고가 안 보일 수 있는 경우(버그 아님): EEA 사용자가 UMP 동의를 거부한 경우, AdMob 계정/유닛 심사 미완료, 신규 유닛의 낮은 fill rate. 출시 후 AdMob 콘솔의 요청 수/매칭률로 확인하면 된다.

**단, Android는 광고가 코드에서 의도적으로 비활성이다** (`MotionFitAdUnits.isSupported`가 iOS만 허용, AndroidManifest는 테스트 앱 ID + "출시 전 교체" 주석). Android 출시 계획이 있다면 Android용 AdMob 앱/유닛 생성과 코드 활성화가 별도 작업으로 필요하다. 이것은 미노출 "버그"가 아니라 미완의 의사결정이다.

부수 관찰(문제 아님, 선택 개선): 하단 네이티브 광고는 세션당 1회 로드 후 갱신하지 않는다. 체류가 긴 사용자에서 노출당 수익을 올리려면 60~120초 주기 refresh를 검토할 수 있다.

## 3. DAU 10배를 막는 문제점 진단

현재 앱은 "도구(tool)"로는 완성도가 높지만 "습관(habit) 제품"의 장치가 없다. 운동 앱의 DAU는 획득보다 리텐션 곡선이 지배한다. 진단:

1. **측정 불능 (가장 치명적)**: 이벤트가 `app_open`뿐이라 어디서 사용자가 이탈하는지 알 수 없다. 10배 성장은 실험 반복인데 실험을 판정할 계기판이 없다.
2. **리텐션 루프 부재**: 스트릭·목표·완료 직후 리마인더 제안이 없어, 첫 운동 후 다시 올 이유를 앱이 만들지 않는다. 리마인더는 존재하지만 기본 꺼짐 + 설정 깊숙이 있어 발견되지 않는다.
3. **첫 실행 마찰**: 온보딩 3페이지 → 홈 → 계획 설정 → 카메라 안내 → 카운트다운을 지나야 첫 가치("자동으로 세준다")를 체험한다. 첫 세션에서 가치 체험까지의 단계가 많다.
4. **바이럴 계수 0**: 공유 기능이 없어 사용자가 사용자를 데려올 경로가 없다.
5. **평점 축적 루프 없음**: 스토어 전환율(ASO)의 핵심인 평점·리뷰를 요청하지 않는다.
6. **코칭 체감 병목**: 시스템 TTS 기본 음성 품질이 "AI 트레이너" 포지셔닝 대비 약하다. 재방문 동기인 "코칭 받는 맛"을 깎는다.
7. **시장 절반 미출시**: Android 빌드는 준비돼 있으나 광고·서명·스토어 구성이 미완료다. 국내외 안드로이드 점유율을 감안하면 TAM 2배 이상이 잠겨 있다.
